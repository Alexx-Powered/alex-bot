# v2.1 自动识别与任务命名

## 数据流

截图 → 蓝色教室标签定位 → 去下划线、提取数字 → 本地中英文 OCR 交叉核验 → 检测8条灰色竖边 → 将7个双节列拆成14节 → 每格区域绿色/白色像素占比 → 结构化数据 → 合并与规划 → 当前任务改名。

程序不内置截图坐标、逐行房号顺序或样本答案。`rules.json`的房号用于校验和位置排序，不用于填补OCR缺失。两种OCR冲突、未知房号、异常颜色只标待核对，不“纠正”为最近房号。

## 输入与输出

`scripts/run.ps1`为首选入口；也可用已有Python运行：

```text
python -B -X utf8 scripts/extract.py screenshot1.png screenshot2.png --out-dir result
```

可提供用户明确的查询日期`--date`；三号楼裁切图缺表头时使用`--assume-building`。不需要截图采集时间。

- `input.json`：房号和14节F/B/?，可直接送入规划器，另有`suggested_title`及`rename_action`。
- `report.txt`：必须直接在对话中完整呈现的Markdown表格和带“推荐原因”的建议，禁止摘录几行代替。
- `result.json`：规划结构化结果，每条建议都有`reason`。
- `cells.csv`：逐格数据。
- `evidence.json`：来源文件SHA256、动态网格坐标、房号OCR原文、颜色占比、原始F/W/?及解释后状态、耗时。
- `review.json`：具体疑点；空数组表示程序未发现疑点，并非对任意截图作绝对正确保证。
- `diagnostics/`：提取后的房号条带与本地OCR结果，供核对。原截图不修改。

用户保证同批截图一定来自同一天，直接合并。日期以用户明确输入优先，其次查询框OCR；OCR日期不一致视为识别疑点，仍按同日数据完成表格，只暂缓依赖日期的标题改名，不要求用户确认是否同一天。所有整段和换房方案只使用F，不拿B或?补齐。

## 空白含义

**绿色一定为空闲，白色一定有课。**原始F绿色直接记录F；原始W白色直接记录B。即使课节已经过去、页面有历史说明、没有采集时间，都不改变此语义。只有实际无法辨色、遮挡、裁切或识别冲突才为?。

v2.1已移除`--blank-policy`和`--captured-at`，不再使用时间推断白格。文件修改时间、当前电脑时间不用于解释色块或推断查询日期。

## 适用边界与失败处理

适用本例直立截图中的蓝色带下划线教室号、灰色竖网格、7个双节列。支持不同尺寸和多张滚动重叠截图。不同主题、拍照透视、额外裁切左列/网格、极小模糊图可能需补图或人工核对。最大边长10000像素；超限时需拆成有重叠且保留表头的截图。Windows无中文OCR时报告缺失；不得静默按模板猜测。

不能确定教室号就不输出该行；颜色不明输出?；网格不符合等距7列就停止该图。其他图继续处理，缺失范围在review.json说明。可在诊断图上复核疑点后按input-format.md修正结构化输入，再运行plan.py；保留修正依据。

## 当前任务自动重命名

格式为`M月D日星期X三号楼自习教室`。`datetime.date.weekday()`按完整查询日期计算星期：2026-10-12生成`10月12日星期一三号楼自习教室`，2026-10-13生成`10月13日星期二三号楼自习教室`。只改当前会话，不改文件夹、不新建项目。代码输出`rename_action`，宿主模型必须读取并实际调用WorkBuddy工具：

```json
{"skill":"/rename","args":"10月13日星期二三号楼自习教室"}
```

本机WorkBuddy打包代码确认：`Skill`接收`skill`和`args`；以`/`开头会路由到内置命令；`/rename`允许模型调用，并对当前上下文session执行rename。备选是`SlashCommand`的`command`参数。返回`Session renamed to:`或`Built-in command executed:`才认为命令成功；宿主若提供读取标题能力，再核验显示标题。错误时报告改名未完成，继续给出表格。不要把`TaskUpdate`的待办标题作为会话标题。

Python进程本身没有当前WorkBuddy会话上下文，因此只生成可执行动作，由调用技能的WorkBuddy模型完成命令调用。这不需要用户再手动输入命令。日期缺失生成null，不猜今天；仍按同一天数据完成分析，仅核对实际日期以便计算星期和改名。
