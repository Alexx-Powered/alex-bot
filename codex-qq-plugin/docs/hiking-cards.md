# 徒步沿线天气卡片

2026-11-07 用户确认第二版预览，授权开发、ECS 上线、更新 RAG 并同步 GitHub。

## 查询与呈现

- `发 徒步 党岭`：今天为第一个徒步日，按参考线路的典型徒步天数生成图片。
- `发 徒步 武功山 2026-11-14 不露营`：指定首个徒步日和住店偏好。
- 自然语言如“周末去党岭徒步，天气怎么样，睡袋带什么温标，有不露营的走法吗？”由受限 `hiking_trip_card` LangChain Tool 执行。
- 沿用 weather 权限；普通聊天关闭仍可通过自然语言工具调用使用。固定命令不读模型配置、不调用理解模型。最终投递仍验证当前群权限，图片回复不附加大段文字。
- 温度、云量、降水三张曲线卡按天横向展开；候选营地整晚低温、睡袋舒适温标、住店替代、已有季节和气候资料、简短公告及来源在下方。最大14个徒步日，超过或未能确定的行程不编造。

## 数据与缺项

路线资料定义步行日、沿途地名和住宿方式。交通日不计入徒步日。首批已核对资料包括党岭三湖穿越/村庄住店、武功山沿线客栈、库拉岗日措玉村三条往返支线。客栈、营地是有资料的候选，不是实时订房或开放保证。

坐标来自带 OSM 要素链接的固定点或 Photon 精确地名匹配。动态匹配检查要素类型、附近锚点与歧义，不接受模型坐标、搜索到的任意 URL 或私人地址。每次最多6个新地名、2线程，地名请求3秒；结果缓存7天、最多512项。每次最多24个代表点。小湖泊无法独立定位时保留空段，不能用村庄天气替代。

ECMWF IFS 经 Open-Meteo 同一批多点请求，15秒、无自动重试；检查位置、时区、单位、逐时连续性和数值范围。最多请求今天起14天，额外一天仅供末小时降水与过夜计算，超出实际覆盖留空。成功结果缓存10分钟、最多4批。来源：[ECMWF API](https://open-meteo.com/en/docs/ecmwf-api)。不把服务商逐时序列解释成原生模式每小时发布。

08—18时按路线点顺序示意进度，其他时段取起点、前晚或当晚住宿点；这不是导航、轨迹或预计到达时刻。位置切换用虚线，未知位置留空。降水读取区间终点 `[h,h+1]` 的 preceding-hour sum；雨量合并 rain 与 showers，雪量用 cm；雨雪总量用 precipitation 的水当量。

2026-11-08按用户反馈调整日汇总：逐字段使用当日已有小时值计算温度范围、平均云量、最大阵风、雨雪累计，不因个别小时缺测抹掉整天。主行程和住店替代采用同一规则；各字段新增可选 `coverage`（0—24个有效小时），不足24小时的有效数值加 `*`，图下注明雨雪仅为已获取时段累计。整日没有该字段仍显示缺测，不以0替代；原曲线空段与切换虚线保持。云量改为当日有效小时平均，不再只用08—18时。旧无coverage的数据仍可渲染。

2026-11-08用户要求按实际 Comfort 舒适温标选择，取消原固定5°C余量。营地20:00至次日08:00共13个温度均有效时，直接以该晚最低预报温度作为 Comfort 上限，不额外减温、不向下取整；全程取各露营夜最低值。只使用 Comfort，不以 Limit/Extreme 代替；夜温缺项仍待补齐，不能用月均温替代。

## 受限更新 RAG

前台只读取本地资料和登记公开路线名；后台不传整段聊天、行程或身份。既有研究队列继续5个待处理、每天20个、成功24小时/失败6小时去重。后台20秒硬截止，最多2次搜索、3页、2下载线程、一次 DeepSeek Flash 结构提取，无工具循环、无重试；搜索12秒预算后仅用剩余时间提取，耗时不足直接保留已有结果。

原文摘录自动写入独立 `research-auto-*` 文档：显著标为未核验引用，保留来源/日期、有效24小时。抽取行程要求逐日同源、连续日序、地名及住宿逐字对应原文证据，不接受距离/坐标/当前通行断言；拒绝否定露营语句、混拼路线和注入文字。合格路线保存7天、最多64种走法，并写入独立 `hiking-auto-*` 文档；人工核对资料使用 `hiking-*`，两者不互相覆盖，也不覆盖校园规则或官方已核对公告。提取不成功不声称已补齐营地。

支持中文日序。只提到营地、未明确帐篷或木屋的资料记为 camp，图片显示“住宿方式待核”，不推定住店或睡袋温标。来源 URL、标题、日期由宿主绑定，只保留实际支撑行程的来源，不把同批查到的政府公告挂成商业路书的出处。模型关闭默认 thinking，只作一次有界提取；搜索链接的页内锚点在完整 URL 校验前规范移除。

规范 SQLite 写入后关键词检索立即可见；既有单一 Python/Milvus 进程每分钟仅在空闲时消费一个 outbox 记录，仅限本地 FastEmbed，不启动第二套 Milvus，不占用模型路由预算。新请求进入时最多遇到一个已开始的小批本地索引操作。外部 embedding 配置不自动消费，需运维原有索引流程。到期原文由现有查询过滤排除；存储容量及索引失败次数上限仍生效。

资料补查不能保证每条路线都找到可靠营地、坐标或住店方案；缺项按实际情况显示，并在后续查询复用合格更新。

## 核验与运行

LangSmith 增加 `hiking_route`、`hiking_locate`、`hiking_fetch`、`hiking_render`，保留原文 Input 规则，数据源失败带固定错误码。仅管理员可使用 `/api/hiking/check` 的固定公开样本；不发送QQ、不允许任意路径、URL、收件人。预览返回的 `mediaReady` 表示同版官方适配器已校验PNG格式和大小，不表示实际QQ送达；renderer统一返回 `{buffer,mimeType}`，端到端离线发送回归必须覆盖核心与QQAdapter。`/api/rag/index` 仅管理员触发一次空闲索引。

生产维护前保留加密备份；研究队列里的新增路线和坐标表随既有 SQLite 备份恢复。候选需通过 map_review（本次不变更地图），本机全量回归，ECS 仅128MiB/50%CPU/无swap串行专项；切换后核对清单哈希、实际监听PID、argv、源码目录及启动时间。
