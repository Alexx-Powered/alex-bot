## 已实现的检索基础

SQLite 独立保存原文、版本、来源、可见范围和有效期；Milvus 只保存向量和定位原文所需的元数据。读取同时执行向量预过滤、SQLite 回源和输出前校验。旧版本、已删除或过期内容不可进入结果。项目记录的保存、删除和索引 outbox 在原文事务内提交；队列满也不阻止删除原文。

共享知识分为 `campus`、`weather`、`bot`；户外资料扩展为 `outdoor`。私人项目摘要使用 `project`，不能作为共享知识导入。会话范围复用已有可信哈希，群与私聊分别保存。新环境缺省关闭，本次生产已由操作员配置启用；校园/天气沿用对应权限，Bot 说明及个人记录暂沿用 `memory` 权限。清空或关闭记忆也清除对应范围的项目原文。

目前返回完整证据片段、来源和版本，尚未把语义相关分数当成答案正确概率。观察结果明确标记 `answer_status=not_assessed`：有关“是否有 WiFi 密码”“是否能证明最佳观赏期”等问题，即使召回主题相关材料，也可能缺少答案。

## 操作员配置

新环境变量 `QQ_RAG_CONFIG` 指向操作员维护的绝对 JSON 路径。文件不可由 QQ 消息或模型指定，建议放入私有运行目录。缺省不加载 Milvus 或 embedding；不改原有固定指令、配额和授权。

配置结构如下，路径需改为当前主机真实绝对路径；不要把带凭据的配置提交 Git。

```json
{
  "enabled": true,
  "store_path": "<绝对路径>/rag-store.sqlite3",
  "embedding": {
    "provider": "fastembed",
    "model_id": "BAAI/bge-small-zh-v1.5",
    "revision": "46fbe35fd4374a00fee7de77dfddaeb6dd6a2c59",
    "dimension": 512,
    "cache_dir": "<绝对路径>/rag-models"
  },
  "vector": {"uri": "<绝对路径>/vectors.db"}
}
```

本地模型必须预先下载对应的固定 HF snapshot；运行时只读本地文件，并将模型文件摘要纳入索引指纹。缺失模型会降级为明确标注的关键词检索，不在处理 QQ 请求时自动下载模型。可配置独立 HTTP embedding，但这意味着把所需原文发送至该端点，必须由操作员明确选择；不会复用聊天模型密钥。

## 资料导入、索引和备份

`data/rag-initial-knowledge.json` 是用户同意收录的现有项目说明和校园查询规则，来源及文件哈希见 `rag-initial-source-audit.json`。其中不包含无依据的插座、安静程度、现场空座或开门承诺。`evals/rag/cases.json` 中的模拟楼宇只能用于测试，不得导入正式知识库。

`data/rag-outdoor-knowledge.json` 补充气象和徒步背景，出处、支持范围、复核期限及冲突见 [气象与户外证据审计](rag-outdoor-sources-20261106.md)。来源包含中国气象局、国家气候中心、Copernicus、地方政府、景区管理部门及应急/体育部门。每条有稳定 ID 和来源日期；旧管制记录不会被当成当前开放状态。共享资料仅从操作员选定文件导入，网页文本不获得工具执行权限。

在插件目录使用单独开发 Python 环境，安装现有 `python/requirements.txt` 与可选 `python/requirements-rag.txt`。实际验证使用 PyMilvus 3.0.2、Milvus Lite 3.2.2、FastEmbed 0.9.1。Milvus Lite 3.x 的 `.db` 是目录，不是可随意单文件复制的旧 2.x 数据库。

```powershell
python scripts/ingest-knowledge.py data/rag-initial-knowledge.json --database <独立SQLite绝对路径> --allow-root <data目录绝对路径>
python scripts/ingest-knowledge.py data/rag-outdoor-knowledge.json --database <同一SQLite绝对路径> --allow-root <data目录绝对路径>
python scripts/index-knowledge.py --config <配置绝对路径> --backup <新备份文件绝对路径>
```

Lite 目录同一时间只由一个进程拥有。当前使用离线维护：先停止专用读取 worker，再处理 outbox，之后启动读取 worker。保存项目记录只写原文和 outbox，不等待 embedding；索引尚未更新时可从词法通道找到有效新版本。索引维护不应与业务读取进程同时争用同一 Lite 目录。

`--requeue` 支持同一模型的索引重建；更换模型需要新索引和受控迁移，不允许直接把不同指纹写进旧集合。`--batches` 限制单次维护工作量，剩余任务留待下次处理；失败到上限后等待诊断和显式重建。SQLite 提供一致性备份；本次已把原文库、气候库和配置接入 `ops/backup.mjs` 加密备份，并完成恢复演练。活跃 Milvus 目录不纳入在线复制，向量可由受保护的原文库重建。

## 新增户外场景的边界

用户追加了气象知识、持续更新的历史气候资料、国内徒步路线和复合出行问答。资料需分层：长期知识进入检索库；历史气候统计进入独立结构化缓存；未来天气实时查询；开放、交通和封闭信息保留公告时效。多年平均、当年物候和周末天气分别判断。

例如党岭出行，需先分清村落周边、具体湖泊路线或高海拔穿越，以及日期、强度、住宿方式和经验。景观季节资料不能证明今年已经达到最佳状态；山脚代表坐标不能覆盖整条高海拔线路。缺少近期开放公告、积雪/路况或物候证据时应列出缺口，不能输出确定的安全结论。

### 气候数据库与更新

`python/climate_history.py` 在独立 SQLite 中保存逐月统计，不把每日数列写入 Milvus。当前取数源为 Open-Meteo Archive API 的明确 `era5` 模型，上游为 ECMWF/Copernicus；不是中国气象局站点实测，也不是直接从 CDS 下载。代码记录模型、取数时间、位置、年份、单位和每月各变量覆盖率。

支持月均温、完整月累计降水、至少 1 mm 降水日数、日最大风速的月均值。三十年参考期固定为 1991—2020，近年段单独保存；未补齐参考期不得称为完整常年值。降水缺测不填零、不按比例放大；十年以上可提供描述性线性变化，但不声称已做统计显著性检验，也不当作未来预报。

`data/climate-locations.json` 是首批明确来源的代表点目录。党岭使用既有地名服务返回的四川丹巴 OSM 点，已排除陕西同名点。它代表地点，不是登山口、湖面、营地或完整线路。政府坐标不是查询代表点的前置要求；若要处理沿线海拔与天气，需要另外提供相应路线数据。

```powershell
python scripts/refresh-climate.py --database <气候SQLite绝对路径> --catalog data/climate-locations.json --place-id dangling --start-year 1991 --end-year latest --max-years 3
# 以下为独立维护示例；生产已使用每天 03:40 的有界 systemd 任务，不另开 watch 进程。
python scripts/refresh-climate.py --database <气候SQLite绝对路径> --catalog data/climate-locations.json --place-id dangling --start-year 1991 --end-year latest --max-years 2 --watch --interval-seconds 3600 --max-runs 0
```

每批最多取三个年份，查询请求只读缓存，不等待历史回填。watch 每轮重算源已可用的完整年份；新鲜缓存复用三十天。失败按年份持久化退避，连续三次后停止该年份自动请求并报告 `needs_attention`；其他未尝试年份仍能继续。查明原因后可用 `--retry-failed` 恢复。逐月逐变量阻止覆盖率退化覆盖已有好数据；跨年、闰年、单位、错位日期及未来时间戳均有回归。

### 复合行程工具

`python/outdoor_planning.py` 的 `prepare_outdoor_trip` 是已实现的独立 LangChain 工具。宿主绑定地点、会话范围和天气权限；模型只填写目的地 ID、起止日期、路线、经验、是否过夜及最高海拔。输出分别保存实时 ECMWF 预报、历史同月资料、路线和装备依据，以及缺失项；单源失败保留其它结果。

日期最多十四天，预报范围超出已支持窗口时明确缺日期。跨月/跨年按行程顺序关联统计；全缺值日期不当作已取到预报。查询不会自动下载气候历史、改记忆、发送 QQ 或将资料全文上传 LangSmith。

复合工具已接入 Agent 并在本次生产启用。通过同一个 `QQ_RAG_CONFIG` 的以下操作员配置注册；缺省或配置无效时不注册该工具，普通 RAG 不受影响。新地点仍需补入可信目录及气候回填，当前不是全国线路全覆盖。

```json
{
  "outdoor": {
```
