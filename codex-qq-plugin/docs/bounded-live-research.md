# 受限实时搜索与知识补充

受限搜索方法与验证历史。正式启用状态、版本和实际 PID 以根 HANDOVER 最新记录为准。下方“原型未接入”等段落保留为上一阶段历史，不能作为当前上线状态。

## 正式接入

`QQ_RAG_CONFIG.research` 可选配置缺省关闭；需顶层 `enabled` 与 `research.enabled` 同时为 true。`queue_path` 固定为运行目录 `.private/research/queue.sqlite3`。已有天气权限同时约束户外补充查询，群关闭天气后不执行此工具或发送在途结果。

正常户外提问可由一次模型路由选 `search_domain_knowledge`，可选 `outdoor_topic` 必须逐字取自当前消息中的公开户外短名。正式资料没有对应主题时，立即登记或读取候选；也可选 `request_outdoor_research` 查看后台结果。不会将整段问题、私人住处、行程、账户或联系人交给搜索接口，不新增模型检索循环。

`alexbot-research.timer` 每15秒检查持久队列；独立oneshot服务仅消费一项。没有任务不解密Key、不调用搜索，只有过期任务也不重搜。服务128MiB、Swap0、CPU50%，启动前至少600MiB可用；网络子进程20秒硬截止，整个服务35秒终止。主QQ不会等该服务，后台也没有QQ发送入口。

搜索固定两条，第一条偏向政府网站，第二条补充公开路线资料；最多3页正文、2页并发，不重试。缺失的搜索摘要/标题不再使合法URL丢失；搜索摘要、生成式summary/content始终不入证据。采购、招投标、征求意见资料不作为徒步线路内容。实体与明确路线描述可拆词匹配，但仍须同段同时出现，不推断别名、坐标或开放范围。

新增来源先进入独立补充资料库。后续问答可确定性展示完整段落、日期线索与来源，明确历史/未核验身份；不把候选传回模型执行指令，不自动覆盖已确认的正式规则。正式库的操作员审核提升机制保留，本次上线没有自动批准开放/安全结论。候选24小时复用，失败6小时冷却；首次问题不会等待网络，也不会完成后追发。

候选库随现有加密备份一并做SQLite一致性快照；缺库则备份失败，不能漏掉。隔离恢复会重写路径并关闭research，避免恢复旧队列后直接联网。启用配置前必须初始化空库。

管理员 `POST /api/research/check` 接受固定 `sample`（moganshan/dongqianhu/xianhu/fudao/haba），默认确定性工具，`mode:natural` 用一次现有模型路由。这是维护测试入口，不接受任意正文/URL/身份/收件人，集成令牌无权访问，不发QQ。实际运行在已有主worker中，禁止第二个Milvus所有者。

四个陌生主题的独立来源证据见 `docs/research-unknown-source-audit-20261107.md`，三轮真实ECS回执见 `test-output/research-release/samples-results.json`。最终3主题取得可用正文，仙湖无相关正文按空结果停止；不同轮次是人工诊断并修改代码后的复测，不是运行时自动重试。完整报告见 `docs/research-release-validation-20261107.md`。

## 方法

正常问答只查已有知识、天气等既有工具。缺少某个明确户外主题时，受限 LangChain Tool 只向独立 SQLite 队列提交公开主题，立即返回任务状态；不等待搜索，不发送整段对话、身份或私人行程。补充任务没有 QQ 发送能力，完成后也不主动追发，后续提问再使用已核验资料。

后台流程固定为：搜索 → 获取有限正文 → 提取有出处的候选 → 结束。没有回到搜索节点的边，也没有 LLM 改写查询或判断“再搜一次”的循环。用可终止子进程包住网络操作，即使 DNS、TLS 或某个同步库卡住，也能在总截止时间到达后结束该任务。

LangGraph 可以表达这个后台无环图，但不能把慢搜索与正常回答放在同一个必须汇合的图里。并行节点共享 super-step，完整调用通常仍须等待；recursion_limit 只限制步数，不保证墙钟时间。当前单主 worker 串行，先采用独立队列/进程边界，避免为了框架改造正常链路。[官方控制流](https://docs.langchain.com/oss/python/langgraph/graph-api-control-flow) · [超时规则](https://docs.langchain.com/oss/python/langgraph/fault-tolerance)

| 限制 | 首版值 |
| --- | --- |
| 搜索查询 | 每任务至多2条固定模板，无分页、无自动重试 |
| 待读候选 | 最多6个链接，正文最多3页 |
| 网络并发 | 全局1个任务，页内至多2个下载 |
| 总时限 | 子进程20秒；搜索最多4秒、正文最多8秒，均受剩余预算约束 |
| 排队与额度 | 队列5条，每天20个新任务，排队超过10分钟取消 |
| 去重 | 同主题仅1个活动任务；成功24小时复用，失败/空结果6小时负缓存 |
| 体积 | 单正文128KiB，独立候选库4MiB、至多256条候选 |
| 大模型 | 搜索/抓取/候选阶段0次，不分配循环推理预算 |

主题必须是短的公开户外名称，不能传 URL、任意命令、密钥或原始聊天。请求不访问私网、元数据地址或任意网页；禁止跳转和自动跟链，来源域由维护者控制，403/429/验证页直接停止对应请求。搜索适配器与网页抓取都有限额；公共搜索接口不可用时明确失败，不轮换一堆站点反复尝试。

直连抓取仅HTTPS；DeepSeek Fetch专用适配器支持其官方允许的公开HTTP/HTTPS目标，HTTP仅默认80，原始URL不改写。API本身始终HTTPS，Key仅发送到固定DeepSeek地址；提交前验证目标白名单及完整DNS均为公网。代理服务器最终DNS/重定向/目标策略由DeepSeek执行，本地不能宣称绑定了代理目标IP；403/404不回退直连绕过。

## 入库与“自进化”的边界

搜索摘要仅用于发现链接，不当作读过的正文。新网页先进独立候选库，记录 URL、发布/抓取时间、正文摘录与哈希；候选不会自动混入已确认校园规则、项目约定、坐标或气候数据。网页里的操作指令都只是外部文本，不会成为工具参数、系统指令或程序配置。

首版允许自动发现与积累候选；正式知识采用维护者核对后提升，保留核查备注与有限有效期。这一步是本轮防止错误持续扩散的实现选择，不是要求每次搜索都向用户弹审批。尤其开放状态、支线范围、最佳季节和安全结论，不能靠“来源是官网”或模型自评就确认。后续可对经过验证的固定官网栏目增加逐字段自动更新规则。

候选24小时新鲜期表示最近抓取时间，不表示文章事实仍然有效。发布时间独立保存，历史公告保留历史身份；相同事件的多站转载也不能作为多份独立证据。候选过期后有界清理（单次最多16条），已审核条目至少保留7天，旧终态任务保留30天，避免候选库满后永久停止。

批准后使用既有 RagStore 写入带出处的短摘要，重复提升幂等；原文词法检索立即可用，向量事件进入既有 outbox。后台抓取进程不打开 Milvus，也不写正式原文库；上线时由唯一拥有者在空闲维护时处理批准项目，不能另开 Lite 写入者或在前台同步做 embedding。

## 验收

“哈巴西坡”必须区分西坡登顶、黑海/双湖徒步等说法。没有正文的官方页面不入库，不把历史宣传当当前开放依据；公告只给一句带日期与适用范围的提示，不妨碍天气或装备资料。

测试应同时记录：实际查询数/正文数、用时与停止原因、首次提交耗时、后台运行时其他工具响应、重复请求是否新增网络调用、硬超时是否真的结束子进程、候选提升前不可被正式库召回、提升后可引用来源，以及失败时正常问答不受影响。助手浏览器检索与机器人适配器实测分别记录，不能互相冒充。

## 本轮哈巴西坡实测

实现文件为 `python/bounded_research.py`、`research_queue.py`、`research_transport.py`、`research_worker.py`，操作员烟测脚本 `scripts/test-bounded-research.py`。这些是隔离原型，尚未注册到正式 Agent、安装后台消费服务或部署到 ECS。`build_research_tool` 已用真实 LangChain invoke 验证；它只登记任务，调用者需绑定本条原文及公开搜索授权。`run_next` 是后台调度入口，前台不得同步调用。

实测回执 `test-output/bounded-search/live-c69651e6/result.json`：登记约7.485ms；后台运行期间既有真实 LangChain 固定换算三次约3.263/0.818/0.731ms，全部正确。这里是在本机隔离并发验证，不是线上QQ延迟或高负载基准。

公共 Bing RSS 两条查询约345ms结束，未获得可用候选，自动正文请求0次、LLM0次、重试0次；重复主题复用同一任务并负缓存，不继续搜索。独立探针还发现该入口会给出单字“哈”的词条，不能据连通性判定其适合正式资料检索。可选 Brave 搜索适配器已实现，但没有配置/调用付费凭据，正式接入仍缺稳定搜索服务。

上述为首次公共源试验结论。随后经用户提示，已核对并接入 DeepSeek 独立 Search/Fetch，接口与 ECS 实测如下；不再需要用户额外提供 Brave/Tavily 凭据。

另一次明确标记为 `operator_supplied_urls` 的正文验证，使用助手限2条查询/3次打开得到的URL清单；该阶段自动搜索次数0，抓取3页约357ms。一页超出128KiB上限被拒绝，一页未得到可用主题摘录，一页进入候选。维护者核对已读全文后，将一条带日期与范围的媒体转述摘要放入**临时测试知识库**；正式库检索前0条、提升后1条，来源URL保留，向量事件留在测试库outbox，没有加载或修改生产Milvus。这不是自动搜索召回成功，也不是已自动确认当前开放。

“哈巴西坡”有双湖/黑海徒步与西坡登顶的用语歧义；本轮来源支持的公告范围是保护区未开发、未开放区域，不能扩大成所有西坡路线。来源身份和缺口见 `test-output/bounded-search/haba-research.json`。[红星新闻公告转述](https://timeline.sohu.com/news/gEFCLBgcid) · [具体西坡登顶事件报道](https://news.ifeng.com/c/8x42nLcwQCg)。正文只作候选数据，操作员摘要仍明确原始公告未取得、支线范围待核，不能给出当前开放或最佳观景期的确定判断。

## DeepSeek Search / Fetch 与 ECS 结果

官方变更记录说明2026-10-17开放独立搜索接口。实际使用 `POST https://api.deepseek.com/v1/tools/search` 与 `/v1/tools/fetch`，复用现有 DeepSeek Key。Search固定 `count=4,need_content=false`，不发送ori_question或localization；摘要只作发现线索，正文独立Fetch。全程没有模型聊天请求或服务端自动工具循环。[官方接口说明](https://api-docs.deepseek.com/guides/search/) · [更新记录](https://api-docs.deepseek.com/updates/)

截至本次核对，搜索和抓取均每1000次成功请求0.75美元；空搜索、失败或超时按官方规则不收费。每任务上限2次搜索+3次Fetch，全部计费时最多0.00375美元；这不包含正常问答的模型费用。[官方定价](https://api-docs.deepseek.com/quick_start/pricing/)

ECS三轮开发诊断分别保留回执，没有自动重试：精确短语首轮未入候选；第二轮发现8条结果，但仅一页通过当时来源筛选且触及4秒页时限；最终修正来源优先排序、明确媒体域及HTTP代理目标支持，把正文单次上限设8秒并保持总20秒，**2次Search/3次Fetch全部完成**。查询模板仅两条预定规则，方向词可拆开检索，但不据此确认不同线路是同一实体。

最终总墙钟 **1386.5ms**，搜索 **652.282ms**、正文 **358.42ms**、正文核验 **3.267ms**；发现8条、保留6个链接、抓取3页、候选3条，重试0、LLM0，重复登记复用同job。独立systemd单元 `alex-research-deepseek-smoke-v3.service` 使用MemoryMax=128MiB、Swap=0、CPU=50%，启动前可用内存675MiB。凭据仅经既有解密模块和私有stdin传给子进程，不写参数、回执或环境变量。
