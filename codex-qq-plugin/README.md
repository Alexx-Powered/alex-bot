# QQ 主服务

通过腾讯 QQ 官方 Bot 接入，提供天气图片、动态气象视频、雷达、AI 服务状态、校园查询和自然语言工具调用。效果图与常用指令见[项目首页](../README.md)。

## 当前架构

- `src/`：QQ 官方 SDK、授权、全局唤醒词、逐群权限、消息排队、媒体上传和控制接口。
- `python/`：LangChain 工具、模型路由、天气数据下载、地图绘制与视频编码。
- `public/`：控制台、帮助与天气图素材、服务商标志。
- `data/`：地名目录、地图与区域资产及其来源记录。
- `test/` 与 `python/test_*.py`：离线回归与模拟接口。
- `ops/`：ECS 发布、备份、服务单元及地图校核。
- `codex-package/`：Codex 插件定义与 QQ 通知 skill。

固定指令直接调用同一套受限工具，不需要模型 Key。自然语言由现有 agent 选择已授权工具；图片与视频查询成功后直接发送成品。模型不获得任意命令执行或任意消息收件人权限。

## 安装与控制台

需要 Node.js 22+ 和 Python 3.10+。Windows 开发依赖：

```powershell
npm ci
.\scripts\install-python-agent.ps1
```

正式实例在 ECS 的 `alexbot.service` 运行，仅使用官方 Bot。本机通过 SSH 隧道访问 `127.0.0.1:19327`，运行 `scripts/open-setup.ps1` 打开配置页。已部署实例的安装、中文字体、浏览器、加密存储与恢复方式见 [ops/README.md](ops/README.md)。不要使用同一组生产凭据启动第二个本机 Bot。

新建独立实例时，在 QQ 开放平台取得官方 AppID / AppSecret，通过配置页保存并连接；在页面生成主人配对码，由本人私聊机器人发送，再回控制台核对确认。已有实例无需重新配对。访问口令、模型 Key、校园凭据和登录状态不写入仓库。

## 群聊与唤醒词

1. 在「群聊与功能」点击「添加群」，填写备注并生成一次性匹配指令。
2. 在目标群 @ 机器人并发送指令，五分钟内回控制台确认群候选。
3. 选择功能后保存。之后每个群都可独立启停、修改功能和管理定时订阅。

官方群身份使用平台 OpenID，备注不等于数字群号。全局词库在任意页面增删改都会同步；各群只保存词的开关，改名保留开关。群内直接 @ 无需前缀，未 @ 时使用已启用的唤醒词加空格。

普通聊天、图片理解、语音理解、记忆和查询工具分别授权。关闭普通聊天仍可用自然语言调用开放的工具；关闭相应工具后不执行，也不发送已在处理的旧结果。`/help` 只展示当前聊天支持的功能、唤醒词和定时订阅。

## 功能与数据

| 功能 | 当前行为 |
| --- | --- |
| 天气简报 | 两日温度、PM2.5、降水概率与云量曲线；天气摘要图形按查询首日匹配 |
| 户外指数 | 上午、下午分别评分，取较好时段展示；规则见 [outdoor-index.md](docs/outdoor-index.md) |
| 预报视频 | 云量、温度、降水、PM2.5 默认 24 小时，可指定 48h；支持城市、省区和大区 |
| 历史云图 | 仅明确请求历史时查询，展示近 6 小时可用卫星观测 |
| 雷达与地点 | 国内站点与全球降水雷达；支持部分景点、山峰、村庄、徒步路线的代表坐标 |
| 服务状态 | OpenAI、DeepSeek、Gemini、Claude、Kimi；故障卡显示影响范围和进展 |
| 校园查询 | 学院路空教室、三号楼简报和自习推荐；需要在控制台配置校园账户 |
| 换算 | 固定单位与全马、半马距离，确定性计算不调用模型 |
| DeepSeek 余额 | 查询已配置 API 账户，受独立群权限控制 |
| 聊天附加能力 | 自然对话、图片与语音理解、隔离的成员记忆，按配置启用 |

云量、温度、降水优先读取 ECMWF IFS，空气质量使用 ECMWF/CAMS。数据缺失、上游失败或降级按实际结果处理，不将视频过渡帧当成新增观测。具体来源、空间范围和缓存策略见[动态视频说明](docs/weather-video.md)。

## 每日 07:30

「早间天气」和「三号楼自习简报」是两个独立开关，默认关闭。`alexbot-group-morning.timer` 按北京时间 07:30 仅生成并发送已订阅项目，不在恢复运行后补发；逐群、逐图幂等，关闭项目会取消其在途结果。

旧 08:00 任务及 OneBot 服务已经停用，不能作为当前启动或故障回退路径。

## 队列与监控

入站指令按队列处理；等待前一条完成不等于触发固定冷却，但白名单、暂停、模型用量和发送限额仍生效。视频使用重任务队列、同源受限并发下载和缓存，以控制小内存主机的峰值。

控制台「响应与监控」及 LangSmith 分别记录排队、模型路由、获取数据、解码、渲染、编码、媒体上传、消息提交。启用远端监控后，Input 包含触发消息原文及工具参数，Error Message 记录实际失败阶段和错误摘要；不会上传访问令牌或模型 Key。群内未触发的背景消息不作为远端 Input 上报。详见[监控说明](docs/latency-monitoring-20261029.md)。

## 开发与验证

```powershell
$env:QQ_PYTHON = (Resolve-Path '.venv/Scripts/python.exe').Path
node --test test/*.test.mjs
.\.venv\Scripts\python.exe -m unittest discover -s python -p 'test_*.py'
```

Linux 可将 `QQ_PYTHON` 指向对应虚拟环境。全量回归在开发机进行；ECS 只做受资源限制的串行专项。Node / Python 协议变更需保持可选参数默认兼容，并验证真实 LangChain 跨语言调用。

本地预览脚本：

- `scripts/preview-weather-report.mjs`：天气图预览。
- `scripts/preview-provider-status.mjs`：服务状态图预览。
- `scripts/verify-registered-map-ink.py`：地图参考线段复核。

发布前运行 `ops/map_review.py`，核验地图资产、备份与回归；切换后检查实际监听 PID、源码路径、启动时间和官方连接状态。开发约定见 [AGENTS.md](../AGENTS.md)，发布记录见 [HANDOVER.md](../HANDOVER.md)。

## Codex 接入

`npm run mcp` 启动 `src/mcp.mjs` 的 stdio MCP 服务，插件定义在 `codex-package/`。可查询连接状态、按授权通知已配对本人、预览天气。插件通过现有服务发送，不另行登录 QQ，也不允许模型任意指定收件人。求助通知规则见插件 skill 和工作区开发约定。
