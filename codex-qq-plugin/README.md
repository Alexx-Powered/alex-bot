## 启动与本人配对

要求 Windows、Node.js 22 或以上。运行目录为 `D:\Projects\Alex Bot\codex-qq-plugin`；首次安装或恢复依赖使用 `npm ci`。

```powershell
Set-Location -LiteralPath 'D:\Projects\Alex Bot\codex-qq-plugin'
.\scripts\start-service.ps1
.\scripts\open-setup.ps1
```

本地设置服务仅监听 `127.0.0.1:19327`。打开脚本读取本机访问口令；不要分享生成的设置地址。AppSecret 只在本地页填写，不放进聊天、MCP 参数或插件安装包。凭据使用 Windows 当前用户 DPAPI 加密，`.private/` 用当前用户 ACL 保护；能以该 Windows 用户身份运行的程序仍在信任边界内。

1. 在 [QQ 开放平台](https://q.qq.com/) 创建机器人，按平台当前规则配置本人内部体验号码、单聊能力及 WebSocket 消息事件，取得 AppID / AppSecret。
2. 在本地设置页保存凭据并连接 QQ；从机器人资料卡进入私聊。
3. 在设置页生成一次性配对码，用本人 QQ 发送 `/pair 配对码`，再回到本地页确认候选身份。
4. 发送 `/ping`，并确认客户端实际收到。不要公开配对码；本版不提供自助替换已配对主人。

以后可显式使用已有凭据自动连接：

```powershell
.\scripts\start-service.ps1 -AutoConnect
```

`-AutoConnect` 只对已保存凭据且已配对的实例尝试连接，不自动配对，也不解除暂停。发送暂停状态跨重启保持；需要恢复时，在本地页检查原因后操作。服务已经运行时，启动脚本直接返回，可在设置页连接现有服务。停止使用 `scripts/stop-service.ps1`。设置 `QQ_BRIDGE_HOME` 时，服务、打开设置页脚本和 MCP 必须使用同一数据目录。

## QQ 命令

以下查询命令可用于已配对本人私聊。白名单群必须加 **梁圣 / 梁祖 / 梁嗨 / 小难梁** 四个前缀之一，并与命令用空白隔开，例如 `梁祖 发 雷达 华北`、`小难梁 发 天气 北京`；无需 @。`梁祖 帮助` 显示群菜单，`梁圣 /ping` 测试连接。没有此前缀、前缀在句子中间、错别字或只有前缀时，不查询、不调用模型、不回复、不计发送额度；已授权群的合规文字仅更新下述内存背景。其他群和频道不触发查询；本人私聊仍沿用下表的无前缀命令。`/pause`、`/status` 及设置管理仅限本人私聊或本机设置页。

| 命令示例 | 结果 |
| --- | --- |
| `帮助`、`菜单`、`/help` | 查看命令 |
| `发 雷达 北京`、`发 雷达 天津` | 仅发官方单站雷达原图，无附文；默认分别为大兴、塘沽站 |
| `发 雷达 全国`、`发 雷达 华北` | 全国或区域雷达拼图 |
| `雷达目录` | 查看区域及各省站点数量 |

| `发 雷达 北京海坨山` | 按官方站名取图；名称有歧义时提示完整名称 |

## 天气与 CAMS 数据含义

天气使用 Open-Meteo 提供的 ECMWF IFS 0.25° 模型数据，汇总逐时温度、相对湿度、雨雪合计降水量和最高逐小时降水概率，结合雨量、降雪与概率给出降雨信号。最高逐小时概率不是全天降雨概率；总降水不等于纯雨量。底层模块支持今日、明日逐时数据，当前 QQ 天气图展示当天温度与逐小时降水概率。[天气数据说明](https://open-meteo.com/en/docs/ecmwf-api)

PM2.5 使用 **CAMS Global / ECMWF，经 Open-Meteo 提供**；与天气查询共用已解析地点的实际坐标，没有直接连接需要账号令牌的 ADS 下载服务。它是约 45 公里网格、原生 3 小时预报经插值后的逐小时浓度曲线，单位 `μg/m³`，**不是站点实测或综合 AQI**。PM2.5 不能代表全部雾霾，也不能直接判断是否有雾。单城天气图展示本城 PM2.5；双城图只画一个城市的 PM2.5，含北京时优先北京，否则取第一个城市，图内明确标注。[空气质量接口](https://open-meteo.com/en/docs/air-quality-api)、[CAMS 官方数据集](https://ads.atmosphere.copernicus.eu/datasets/cams-global-atmospheric-composition-forecasts)

天气、空气质量及三联图不再使用城市白名单。地名优先匹配和风官方公开地点目录的完整快照（市、区县及来源提供的部分乡镇），其余地名通过 Open-Meteo / GeoNames 地理编码查询；数据范围、源版本和下载时间保存在 `data/weather-locations.json`。这份地点目录不等同于最新行政区划全集，也不承诺每个村镇可识别。来源只提供坐标映射，不使用需要密钥的和风天气接口。坐标和标题贯穿查询与绘图；同名地点列出带行政限定及稳定 ID 的选项，不擅自选首项。所有图表日期、小时仍明确使用北京时间 UTC+8。[和风地点目录说明](https://dev.qweather.com/docs/resource/location-list/)、[Open-Meteo 地理编码说明](https://open-meteo.com/en/docs/geocoding-api)

## 古月币、马里与马时换算

新业务功能默认使用 Python LangChain，约定保存在项目根目录的 `AGENTS.md`。换算实现位于 `python/conversions.py`，由 `agent_worker.py` 的 `convert_units` LangChain Tool 统一执行；Node 只规范输入、路由和校验返回格式。

| 自定义单位 | 固定关系 |
| --- | --- |
| 古月币／HU$ | 0.6 HU$ = 70 人民币；1 HU$ ≈ 116.666667 元 |
| 马里 | 1 马里 = 3.08 km = 3080 m |
| 马时 | 1 马时 = 1.5 小时 = 90 分钟 |

均支持双向换算。本人私聊可发 `换算 0.6 HU$ 人民币`、`70元换古月币`、`1马里换公里`、`1马时换小时`；群里加既有前缀，例如 `梁祖 换算 0.6 HU$ 人民币`。人民币别名支持元/CNY/RMB，距离支持公里/千米/km/米/m，时间支持小时/h/分钟/min；也支持 `HU$0.6` 写法。固定数值格式无需模型Key，不计模型额度，仍计QQ实际发送额度。

模糊问法如“我手里有0.6古月币，折合多少人民币呀”由现有模型选择同一工具，计入模型请求预算。工具直接输出一行结果，不加角色闲聊、不由模型重算。比例为本地固定值，群消息不能改写；古月币没有钱包或交易接口，也不使用实时外汇数据。数值只接受非负十进制，最多12位整数、8位小数；结果最多6位小数，舍入时标 `≈`。不同类别不能互换，失败时不会改用模型心算。
