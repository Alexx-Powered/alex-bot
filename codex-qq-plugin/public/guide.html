01 / OVERVIEW

不用一直开着 Codex，也能运行

QQ 接入与本地服务

Node.js 维护官方 QQ 连接，检查本人和群权限名单、群前缀、暂停及发送额度，再把可处理的请求交给业务层。

Python 与 LangChain

把工具参数、模型选工具、上下文和结果处理组织起来。模型通过 DeepSeek 在线 API 调用，不是在电脑上运行模型权重。

独立的定时脚本

Windows 用户登录后启动服务和日报调度器。不依赖 Codex 保持打开；电脑关机、休眠或断网时无法正常查询和发送。

QQ 桌面客户端不承担机器人运行。机器人使用独立的官方连接，不修改、不注入 QQ 客户端。本机页面只监听 127.0.0.1:19327，没有部署到云端。

日常怎么打开

  1. 登录 Windows：已安装的 AlexQQ-Morning-Service 任务启动后台调度器。
  2. 双击桌面的“亚历克斯 Bot”快捷方式：服务未启动时先启动，再打开带本机授权的配置页。
  3. 在 QQ 私聊直接提问。群聊以“梁祖 ”等前缀开头，例如“梁祖 北京今天要带伞吗”。收发均不需要 @。

关闭浏览器不会停止服务。配置页“暂停发送”会跨重启保留；打开快捷方式不会解除暂停。登录启动不等于开机后无人登录也能运行。

02 / MESSAGE FLOW

一条消息，走哪条路径？

QQ 消息本人私聊 / 已授权群
↓
本地入口检查白/灰名单 · 群前缀 · 暂停 · 安全与并发限制
↓ 按请求类型分流
明确的固定命令例如：发 雷达 华北
↓ 不调用模型
直接执行受限工具
自然语言 + 有限上下文例如：北京今天要带伞吗？
↓ 检查模型额度
LangChain agent → DeepSeek理解意图，选择工具和参数；缺信息则澄清
↓ 本地校验参数和权限
执行选中的工具查询 / 计算 / 许可范围内的聊天
↓
结果处理与 QQ 发送图片直接发；换算、预算、状态可再用一次模型解释；发送仍需通过本地检查

例如“我跑了个全马，大概是多少马里”：模型把“全马”对应到标准距离，工具按固定比例算出约 13.7 马里，再由模型结合问题自然解释。计算结果来自代码，模型负责理解和表达。

当前 agent 是有边界的单次工具选择流程，不是无限循环执行任务。天气工具在 Python 侧定义，现有数据获取和图片渲染通过本地 RPC 复用 Node.js 实现。固定天气命令在 Python worker 不可用且尚未执行工具时，也有本地降级路径。

04 / LEARN LANGCHAIN

LangChain 的优势，落在哪里？

1

同一个工具，多种问法

“北京雷达图”“看看北京附近的雨云”可以由模型映射到同一个雷达工具，不必为每种说法编写关键词分支。是否调用成功仍取决于意图识别、参数和数据源。

2

模型理解，代码执行

工具声明告诉模型“有什么能力、需要什么参数”。程序校验参数后才执行。模型不会直接拥有任意网址访问、文件操作或 QQ 收件人选择权。

3

同样的工具，也能定时用

工具不一定要由模型调用。明确命令和早安报告可直接调用工具，减少费用与不确定性；自然语言则保留灵活性。

一次自然语言请求，实际发生了什么

  1. 组装输入：当前问题、允许的聊天背景、本地角色规则和可用工具说明。
  2. 调用模型：LangChain 把这些发给 DeepSeek；模型返回工具名和结构化参数，或选择聊天、澄清。
  3. 执行工具：本地校验参数、范围和权限，运行查询或固定计算。
  4. 返回结果：图片直接发送。适合解释的数值或服务状态，可再调用一次无工具权限的模型；解释失败保留真实工具结果。

LangChain 是组织模型和工具的框架，不是模型本身，也不是“接上以后就会自动理解一切”。工具说明、系统提示词、上下文隔离和异常处理仍需开发者明确设计。

跟进问题为什么需要上下文？

“那天津呢？”本身缺少要查什么。最近对话能帮助模型知道是在问天气还是空气质量。但当前明确意图优先，不能因为上轮聊了天气，就把“我还有多少余额”误当成缺地点的天气请求。

私聊保留最近 3 轮、15 分钟；授权群保留启动后实际收到的最近 10 条文字、30 分钟。群背景使用匿名标识，但文字本身仍可能包含个人信息。切换名单、移除、暂停、断开及重启会清除相应内存；不能读取历史 QQ 聊天记录。

05 / SCHEDULE

早安报告：固定时间，固定规则

Windows 登录

任务计划启动调度器，检查本地服务。

北京时间 08:00

已开机联网则发送；晚于 08:00 启动则检查并补发当天报告。

选择城市与时段

普通日用北京；已配置的官方法定节假日用天津。普通周末不因此改成天津。

生成并发送

天气、空气质量与运动建议合成报告，仅发本人私聊。

日期情况重点分析的运动时段
正常工作日的周一、周三20:00–22:00
其他日子07:00–08:30、16:00–19:00、20:00–22:00

运动建议基于温湿度、降水、风、日晒和空气质量等数据，由 Python 固定规则评估；不需要在线大模型。数据缺失时会注明，不能把“未知”当作适宜运动。

发送前先记下当日尝试，避免崩溃或送达不确定时重复发送。因此“每天一份”是去重策略，不是保证送达；失败不会反复补发。暂停、离线、未配对或本地额度不足时不发送。调度器约每 15 秒检查一次，不承诺秒级准点。未来年份需要更新节假日资料；本页不提供新增计划或改收件人的操作。

06 / CODEX CONNECTION

Codex 插件是另一条受控入口

正在运行的 Codex 任务
↓ MCP 工具
本机桥接 API状态、授权、暂停、幂等和发送额度检查
↓
官方 QQ → 本人 / 已明确授权的白名单广播

Codex 使用 qq_status 检查状态，qq_notify 给本人发通知；qq_broadcast 仅用于用户明确授权的白名单广播。另有 qq_weather_preview、qq_weather_briefing 和 qq_morning_test 用于天气预览、本人日报与明确授权的测试。

现有求助规则：同一阻塞经至少 3 次有意义的安全诊断仍未解决，在 Codex 提出具体问题后至少 5 分钟未获回复，并确认机器人已连接、已配对且未暂停，才向本人尝试发送一次简短求助。同一阻塞不循环催促，失败或送达不确定也不换键重发。

QQ 聊天 agent 不控制 Codex，也不会把普通 QQ 回复当成执行审批。Codex 求助规则由当前 Codex 任务执行；任务结束、应用退出或电脑休眠后不会独立运行。

07 / BOUNDARIES

模型调用与发送规则

环节当前规则
触发范围已配对本人私聊；已确认白/灰名单群的前缀消息；白名单全部业务、灰名单基础聊天和换算。前缀为“梁圣 / 梁祖 / 梁嗨 / 小难梁”，后接空白。普通群文字不回复、不调用模型。
模型逻辑请求每人 9 次/60 秒、每会话范围 12 次/60 秒、全局 15 次/60 秒、每日 180 次。无固定冷却；失败和忽略也计数，重启不清额度。
一次请求的模型开销通常一次工具选择；换算、预算和状态解释可增加一次无工具推理。单次推理超时 20 秒、最多 768 tokens。仅工具执行前的连接类失败允许一次有限重试；不是所有错误都会重试。逻辑请求数不等于供应商实际 API 次数。
输入与回复输入最多 320 字符、3 行；回复安全上限 600 字符，部分解释更短。不按两句或固定短模板回答。复杂代码、长文、链接、附件及可识别的显式注入被本地限制。
并发与 QQ 发送普通入站执行和等待合计最多 4 个；QQ 发送尝试每分钟 15 次、每天 300 次，其中 10 次保留主动通知。它们是本地限制，不代表 QQ 平台授予的额度；以设置页实时数据为准。
数据与权限Key 使用 Windows 当前用户加密保存。模型接收当前问题和筛选后的上下文，不得到 Key。模型不能改比例、改权限名单、指定任意收件人、读文件或执行系统命令。
失败处理区分模型连接、认证、余额、限流等错误；不编造查询结果。QQ 发送失败不盲目重试，平台错误可暂停发送。安全过滤不能保证识别所有注入。
没有模型或模型暂时不可用，还能做什么？

固定天气/雷达命令、明确换算命令、明确的“查 DeepSeek 余额”、固定规则早安报告，以及独立的 Codex 插件通道仍可按各自条件运行。自然语言理解和聊天需要模型服务可用。所有线上数据查询和 QQ 发送仍然需要网络。

以后增加一个功能

  1. 先写能独立验证的 Python 查询或计算函数，明确输入、输出、错误和允许访问的数据源。
  2. 封装为 LangChain Tool，写清用途和参数约束；把权限限制放在代码里，不只写在提示词里。
